# 접근 11 — 쌍둥이 행 처리 + KIRC/KIPAN·GBMLGG/LGG 전용 서브모델

## 개요
KIRC(신장 투명세포암)/KIPAN(신장암 전체), GBMLGG(교모세포종+저등급 신경교종)/LGG(저등급 신경교종) 문제를 approach10(새 피처 추가)과 다른 방식으로 풀어보려는 시도임 — 피처를 더 얹는 대신, 데이터 정제와 모델 구조 자체를 바꿔봄. 

코드 폴더: `4. src/common/approach11_twin_handling/`

## 상세

### v1 — 쌍둥이 행 학습 제거 (`approach11_v1_twin_removal.py`)
기반은 approach1 v2+approach2 v1·v2(코드명 `v4`), 새 피처 없음. train에서 KIPAN/KIRC·GBMLGG/LGG 완전동일 프로필 행(1,005행)을 학습 데이터에서만 제거하고 학습함(검증은 원본 그대로 유지). fold당 학습 행이 4,960→4,130대로 급감, 정보 손실이 잡음 제거 이득보다 커서 4개 타겟 클래스·전체 전부 악화됨.

### v2 — KIRC/KIPAN, GBMLGG/LGG 전용 서브모델, 가중치 없음 (`approach11_v2_specialist_submodel.py`)
기반은 v4와 동일, 데이터 정제 없음. 26클래스 전체가 아니라 KIRC/KIPAN 두 클래스만, 또는 GBMLGG/LGG 두 클래스만 골라서 별도의 2-클래스 전용 모델을 새로 학습함(메인 모델과 무관, 비교용).

### v3 — 위 + 클래스 가중치 (`approach11_v3_specialist_submodel_balanced.py`)
v2와 동일 구성 + 전용모델 학습 시 `class_weights()`(`4. src/common/main.py`에 이미 있는 함수 재사용)를 `sample_weight`로 추가함. 다수 클래스(GBMLGG, KIPAN) 쪽으로 쏠리는 편향이 2클래스로 좁히니 더 심해지는 부작용이 있어서, v2·v3 둘 다 단독으로는 안 쓰고 v4의 재료로만 사용함.

### v4 — 라우팅 앙상블 (`approach11_v4_specialist_ensemble.py`)
기반 v4(메인 26클래스 모델) + v3의 GBMLGG/LGG 전용 서브모델(가중치 적용). 앙상블 규칙: 메인 모델의 1차 예측이 GBMLGG 또는 LGG일 때만, 그 최종 답을 전용 서브모델의 판단으로 덮어씀(그 외 24개 클래스는 메인 모델 그대로 둠). GBMLGG 정밀도 일부 희생(0.5052→0.4848), LGG는 크게 회복(0.4348→0.4870). 재실행 시각이 다른 두 번의 실행에서 소수점까지 완전히 동일한 결과 확인됨.

### v5 — v7 최고 LB 설정 + 라우팅 앙상블 (`approach11_v5_v7_routing_submission.py`)
성민님이 2026-09-11 오전에 확인한 신규 최고 LB(v7, colsample_bytree 0.7 + 복원 배율, LB 0.4377)와 동일한 메인 모델 설정에, v4의 GBMLGG/LGG 라우팅 규칙을 그대로 결합함. 메인 모델은 test 전체(2,546행)에 대해 배율까지 적용한 뒤 argmax로 1차 예측을 내고, 그중 GBMLGG/LGG로 예측된 163행만 별도로 학습한 전용 서브모델(가중치 적용)의 판정으로 덮어씀 — v4와 동일하게 정답 라벨 없이 메인 모델의 1차 예측만으로 라우팅하므로 실제 추론에 그대로 쓸 수 있는 형태임. 12행의 예측이 바뀜.
제출 전 정직 CV로 과적합 여부를 재확인함: mild_col(v7과 동일 파라미터) 메인 단독 0.4669, 라우팅 적용 시 0.4693(+0.0024, v4의 +0.0012와 같은 방향·재현 확인) — CV 붕괴 등 이상 신호 없음을 확인 후 제출.
**12차로 리더보드 제출함(쌍둥이 규칙 미적용본, `approach11_v5_20260911_1420.csv`) → LB 0.4331.** v7 단독(0.4377)보다 **−0.0046 낮음 — 라우팅 앙상블이 실제로는 역효과.** CV에서는 개선(+0.0024)이었는데 LB에서는 반대로 나와, CV↔LB 무상관이 또 한 번 확인됨.

### v6 — 쌍둥이 제거 + 단순 모델 + 신뢰도 임계값 보정판 (`approach11_v6_twin_excluded_soft_routing.py`)
v5 실패 원인(쌍둥이 노이즈 + 4,384차원 대비 표본 52개 과적합)을 보정: 서브모델 학습에서 쌍둥이 제외, XGBoost 대신 로지스틱회귀, 검증행이 쌍둥이면 라우팅 자체를 생략, 서브모델 확률이 임계값(0.6/0.7/0.8) 이상일 때만 덮어씀. 시드 5개로 반복 측정한 결과 개선폭이 표준편차보다 훨씬 작아 노이즈 수준으로 판정, **라우팅 자체를 시도하지 않음(미제출).**

### v7 — 저차원 마커 서브모델 (`approach11_v7_lowdim_loocv.py`, `approach11_v7b_lowdim_5fold_isolation.py`)
v6까지는 서브모델 입력이 계속 `FeatureMaker("v4")`(수천 차원) 전체였음 — 표본(52~338) << 피처(4,384)인 상황에서 차원의 저주가 원인일 수 있다는 가설로, 입력을 문헌 근거 있는 6개 유전자(IDH1/EGFR/ATRX/PTEN/IDH2/TP53, `approach9_gene_override/known_gene_roles.py` 참고)로 확 줄여봄. 비쌍둥이 338행(GBMLGG 286 + LGG 52)에 로지스틱회귀로 LOOCV를 돌린 결과 macro F1 0.7295, **LGG 재현율이 32.7%→78.8%로 크게 개선됨.** v7b로 LOOCV를 5-fold(5시드)로 바꿔 재확인한 결과 거의 동일(0.7147~0.7295)해서, **개선 원인이 차원 축소이지 평가 방식(LOOCV)이 아님을 확인함.**

**주의**: 이 macro F1 0.7295는 GBMLGG/LGG 두 클래스만의 이진분류 문제에서 측정한 것이며, 26클래스 전체 파이프라인에 라우팅으로 통합했을 때의 효과는 아직 별도로 확인 안 됨(v4/v5와 같은 방식의 통합 테스트가 다음 단계로 필요). LGG 정밀도는 45%로 낮음(위양성 50건) — "LGG라고 예측한 것의 절반 이상이 실제로는 GBMLGG"라는 뜻이라 개선 여지가 남아있음.

### v8 — 정밀도 개선 3가지 시도, 전부 실패 (`approach11_v8_precision_tuning.py`)
v7의 LGG 정밀도가 45%로 낮은 문제(위양성 50건, "LGG"라고 예측한 것의 절반 이상이 실제 GBMLGG)를 고쳐보려 세 가지를 시도함: ① 마커 6→10개 확장, ② `known_gene_roles.py`의 "IDH1+ATRX 동반=성상세포종 아형(WHO 기준)" 조합 피처 추가, ③ 확률 임계값을 0.4~0.7로 스윕. **셋 다 정밀도를 44~45%에서 못 움직였음.**

**임계값이 안 통한 이유**: 임계값은 "확신이 부족해서 생기는 실수"를 걸러내는 장치인데, 이 위양성들은 확신이 부족해서 틀리는 게 아니라 **"마커 패턴 자체가 진짜로 LGG처럼 보이는 GBMLGG 행"이라 높은 확신으로 확신을 갖고 틀림.** 그래서 임계값을 0.7까지 올려도 정밀도는 그대로였고 재현율만 떨어짐(76%→69%).

**정밀도와 재현율이 같은 행에서 나오는 구조**: 로지스틱회귀는 "GBMLGG 기본값 + LGG 예외 판정" 2단계가 아니라 **모든 마커를 합쳐 LGG 확률 하나를 계산하는 단일 저울**이라, "진짜 GBMLGG인데 LGG로 잘못 찍은" 행 하나가 GBMLGG 재현율과 LGG 정밀도를 동시에 깎음 — 서로 다른 두 문제가 아니라 같은 행이 만드는 하나의 현상.

**"그럼 애매한 건 GBMLGG로 되돌리면 안 되나?"**: 위양성 50개와 진짜 정답 41개가 **마커 공간에서 통계적으로 구분이 안 됨**(둘 다 IDH1 있음+ATRX 있음+EGFR 없음, 같은 패턴). 구분이 안 되니 "애매한 것만 골라 되돌리기"가 불가능하고, 전부 되돌리면 마커를 안 쓴 것과 같아져 "무조건 GBMLGG" 기준선(macro F1 0.458)으로 돌아가 버림 — 지금(0.7295)보다 훨씬 나쁨. **50개를 잘못 맞히는 손해가 41개를 놓치는 손해보다 Macro F1 관점에서 작아서, 지금 방식(마커가 시키는 대로 LGG)이 맞는 선택.**

**해석(추정)**: 이 한계는 마커가 부족해서가 아니라, **GBMLGG 라벨 자체가 생물학적 하위분류가 아니라 코호트 소속(어느 연구에 뽑혔는지)이라서 생기는 구조적 문제**로 보임 — 일부 GBMLGG 라벨 행은 생물학적으로는 LGG스러운 마커 프로필을 갖고 있지만 코호트 소속상 GBMLGG로 남아있을 수 있음(1번 섹션 "여권과 명단" 비유). 현재 갖고 있는 유전자 변이 정보로는 "생물학적 특성"까지는 알아내도 "어느 코호트에 뽑혔는지"까지는 알아낼 수 없어서, **지금까지 시도한 방법들로는 이 정밀도 한계를 넘지 못했음** (다른 방법으로 완전히 불가능하다고 단정하긴 어렵지만, 마커 확장·조합·임계값을 다 시도해도 안 움직였다는 건 강한 정황 증거).

## 결론(v1~v8 시점) — v4·v5·v6는 폐기, v7(저차원)은 유망하나 통합 테스트 필요
- v1(쌍둥이 행 제거)은 명확한 역효과라 폐기함.
- v2·v3(전용 서브모델 단독)은 단독으로 쓰지 않고 v4의 재료로만 사용함.
- v4(라우팅 앙상블)는 train 정직 CV 기준으로는 유일하게 재현 가능한 양(+)의 결과였음(+0.0012).
- **v5(v4 로직을 실제 test에 적용)는 LB 0.4331로 v7(=성민님 v7, 별개)보다 −0.0046 하락함.** CV 개선이 LB 개선으로 이어지지 않는다는 팀의 기존 결론(`5. submissions/README.md` "CV ↔ LB 대응")이 이번에도 그대로 재현됨.
- **v6(쌍둥이 제거 + 단순 모델 + 임계값)은 CV 자체에서도 개선이 없어(노이즈 수준) 서브모델+하드/소프트 라우팅이라는 큰 틀은 여기서 사실상 폐기됨.**
- **v7(저차원 마커 서브모델)은 GBMLGG/LGG 이진분류 자체는 크게 개선됨(LGG 재현율 2.4배).** 다만 26클래스 macro F1에 실제로 도움이 되는지는 아직 미확인 — **다음 단계는 이 저차원 서브모델을 메인 파이프라인에 라우팅으로 통합해 반복 CV로 검증하는 것.**

### v9(a/b/c) 결론 — v7의 원래 구성이 지금까지 최선
비선형 모델·자동 유전자 탐색·심각도 피처 셋 다 v7(문헌 마커 6개 + 이진 + 로지스틱회귀 + 임계값 0.5, macro F1 0.7224~0.7295)을 못 넘음. 여러 축을 다르게 바꿔봐도 0.72 근처에서 안 움직이는 게 안정적인 천장으로 보임 — **정밀도 개선 시도는 여기서 마무리, v7 원래 구성 그대로 다음 단계(26클래스 통합 테스트)로 진행.**

### v10 — KIRC/KIPAN에도 저차원 마커 방식 적용 (`approach11_v10_kirc_kipan_lowdim.py`)
GBMLGG/LGG에서 통한 방식(문헌 마커 + 로지스틱회귀)을 KIRC/KIPAN에도 적용. 패널에 있는 문헌 마커 10개(VHL/MTOR/TP53/PTEN/MET/NF2/FH/PIK3CA/TSC1/CDKN2A) 사용 — 핵심 driver인 PBRM1/SETD2/BAP1은 패널에 없어 제외.

비쌍둥이 표본 296(KIRC 58, KIPAN 238), 5-fold(5시드) 결과: **macro F1 0.6116, KIRC 재현율 36.6%** (기존 XGBoost 전체차원 서브모델의 17~21%에서 약 2배 개선). 다만 무조건 KIPAN 예측 기준선(macro F1 0.446) 대비 개선폭(+0.166)이 **GBMLGG/LGG의 개선폭(0.458→0.7295, +0.27)의 절반 수준**에 그침 — 핵심 driver 유전자 부재가 원인으로 추정(VHL 하나만으로는 KIRC 45%/KIPAN 30% 차이가 IDH1의 41%/78.6% 차이만큼 극적이지 않음).

**결론: 개선은 확인되나 GBMLGG/LGG만큼 유망하지 않음. 우선순위는 GBMLGG/LGG 통합 테스트가 먼저, KIRC/KIPAN은 후순위.**

### v10b — KIRC/KIPAN에 v9(a/b/c) 보정 동일 적용 (`approach11_v10b_kirc_kipan_tuning.py`)
GBMLGG/LGG에서 시도한 비선형 모델·카이제곱 자동탐색·변이 심각도 3가지를 동일하게 적용(전부 5-fold 기준). 비선형(SVM 0.5872/결정나무 0.6298)과 카이제곱(0.6260)은 기준(0.6116)보다 근소 우위, 변이 심각도(0.6087)는 차이 없음 — GBMLGG/LGG(전부 실패)와 다른 패턴. 다만 신호가 약한 클래스라 5-fold 추정치 자체의 신뢰도가 낮음(v10d 참고).

### v10c — KIRC/KIPAN 정밀도 개선 3종 (`approach11_v10c_kirc_kipan_precision.py`)
GBMLGG/LGG v8과 동일하게 조합피처(`VHL&~MET`, `MET&~VHL` — approach10_v1 아이디어 재사용)와 임계값 스윕(0.4~0.7) 시도. **임계값 0.4에서 macro F1 0.3509로 붕괴**(재현율 96.2%, 정밀도 22.7%) — KIRC가 KIPAN의 4분의 1도 안 되는 소수클래스라 임계값에 훨씬 민감함을 확인. 임계값 0.6이 최선(0.6250, 5-fold 기준)이나 GBMLGG/LGG만큼 뚜렷한 개선은 아님.

### v10d — LOOCV 재검증 (`approach11_v10d_kirc_kipan_loocv.py`)
v10 기준(10개 마커, 로지스틱회귀)을 LOOCV로 재확인한 결과 **macro F1 0.5872 — 5-fold(0.6116)보다 −0.024 낮음.** GBMLGG/LGG(LGG 52개)에서는 LOOCV와 5-fold가 거의 동일했는데, KIRC(58개, 표본은 더 많음)에서는 유의미하게 다름 — **원인은 표본 수가 아니라 마커 신호의 강도**로 추정(VHL 45%/30% 차이는 IDH1의 41%/78.6% 차이보다 훨씬 약함). **KIRC/KIPAN의 공식 수치는 이후 LOOCV 값(0.5872)을 사용.**

**KIRC/KIPAN 쌍둥이 비율 재분석**: KIRC는 전체의 **82.6%가 쌍둥이**(GBMLGG 38.0%보다 훨씬 높음) — 마커 기반 서브모델이 손댈 수 있는 영역(비쌍둥이 58행)이 KIRC 전체의 5분의 1도 안 됨. **LB 개선의 핵심 레버는 서브모델 고도화가 아니라 twin_rule이 이 클래스 쌍에서 제대로 작동하는지 확인하는 쪽으로 보임.** (전 클래스 비교는 `3. docs/07_class_specific_analysis.md` 참고)

## 방법론 메모 — 표본이 적은 서브모델의 검증 방식 (v10d 이후 수정)
v7/v7b(GBMLGG/LGG, n=338)에서는 LOOCV와 5-fold가 사실상 동일했지만, v10d(KIRC/KIPAN, KIRC=58개로 오히려 표본이 더 많음)에서는 −0.024로 유의미하게 달랐음. **표본 수만으로는 예측이 안 되고, 마커 신호의 강도가 진짜 원인으로 추정됨** — 신호가 강하면(IDH1) fold 구성과 무관하게 안정적이지만, 신호가 약하면(VHL) fold 구성(운)에 결과가 크게 흔들림.

**개정된 규칙**: "표본 30개 미만일 때만 LOOCV"라는 이전 기준은 폐기. **표본이 100개 미만인 서브모델은 본 계산 전에 LOOCV와 5-fold를 둘 다 빠르게 돌려서 비교하고, 차이가 크면(대략 0.02 이상) LOOCV 값을 공식 수치로 채택한다.** 신호 강도는 사전에 알 수 없어서, 매번 실제로 비교하는 것이 유일하게 믿을 수 있는 방법.

### 방법론 정정(1차) — twin_rule과 라우팅은 (d) 보정 이후 서로 겹치지 않음
당초 "twin_rule과 라우팅을 동시에 켜면 변별력이 떨어진다"고 판단했으나 재검토 결과 부정확했음. v6부터 반영된 보정 (d)("검증/추론 행이 train과 프로필이 완전히 같으면 라우팅 자체를 생략하고 메인 모델에 맡김")가 이미 들어가 있으면, **TwinRule이 건드리는 행(쌍둥이 매칭)과 라우팅이 건드리는 행(비쌍둥이 GBMLGG/LGG)은 서로소(겹치지 않음)**. 이 자체는 여전히 맞음(라우팅과 twin_rule은 실제 test 추론에서 서로 간섭하지 않음).

### 방법론 정정(2차, v11에서 확인) — twin_rule 효과는 정직 CV로 아예 측정 불가능
1차 정정에서 "그러니 통합 테스트에서 twin_rule의 CV 효과도 같이 확인 가능하다"고 했는데, **이건 틀렸음.** v11에서 라우팅과 라우팅+twin_rule의 결과가 5시드 전부 완전히 동일하게 나와(매칭 0건) 원인을 재확인함:

**정직 CV(`twin_groups`)는 쌍둥이 그룹을 통째로 같은 fold에 묶어서, 검증 행의 쌍둥이 짝이 학습 fold로 새지 않게 만드는 장치다.** 반면 twin_rule은 정확히 그 반대 상황(검증/test 행의 쌍둥이 짝이 학습 데이터 쪽에 있는 경우)을 이용하는 규칙이다. **즉 정직 CV가 막으려는 상황을 twin_rule은 이용하므로, 정직 CV 안에서는 twin_rule이 매칭을 찾을 상황 자체가 원천적으로 생기지 않는다.**

**실제 test에서는 다름**: approach11_v5 실행 시 이미 확인됨 — "train과 완전 동일 행 235개(test의 9.2%)". 정직 CV(매칭 0%)와 실제 test(매칭 9.2%)의 차이가 이 구조적 문제를 직접 증명함.

**결론: twin_rule의 효과는 정직 CV로 절대 측정할 수 없고, 오직 실제 리더보드 제출로만 확인 가능함.** (v4/v5/v6/v11에서 반복 확인된 "CV가 LB를 못 맞힌다"는 것과는 또 다른, "이 방법론으로는 CV 측정 자체가 원천적으로 불가능하다"는 더 강한 제약임.)

### v13 — GBMLGG/LGG + KIRC/KIPAN 동시 라우팅, 효과 누적 검증 (`approach11_v13_combined_routing.py`)

|---|---|---|---|---|
| 평균 | 0.4595 | 0.4602(+0.0007) | 0.4602(+0.0007) | **0.4609(+0.0014)** |

v16까지는 "배율 끈 상태" 대비 개선을 봤는데, **진짜 중요한 질문은 "class_scale을 그대로 둔 최선(라우팅 없음)"과 비교해 절대적으로 더 나은가**임. 기준선 = class_scale 정상 적용 + 라우팅 없음.

| 비교 | 기준선 대비 delta 평균 | 표준편차 | 비율 | 기준선보다 높은 시드 |
|---|---|---|---|---|
| A) GBMLGG/LGG만 배율끄고 라우팅 | -0.00253 | 0.00064 | -3.94 | **0/5** |
| B) KIRC/KIPAN만 배율끄고 라우팅 | -0.00250 | 0.00045 | -5.56 | **0/5** |

**최종 결론: GBMLGG/LGG·KIRC/KIPAN 라우팅은 어떤 조합으로도 class_scale 단독보다 LB 잠재력이 높지 않음. 이 방향은 여기서 완전히 종료.**

### v21 — STES 위험 발견, 절충안 검토 (test 실제 추론 포함)
"v7 전용 재계산(기존 그리드)"으로 **실제 test.csv에 추론**해본 결과(`4. src/submissions_source/classscale_refit_v7mildcol_20260912.py`):
- **train 정직 CV 안에서는 STES 예측 비율이 6.8%로 정상**(실제 6.1%와 거의 일치, 문제 없어 보임)
- **그런데 실제 test 추론에서는 STES 예측 비율이 23.3%까지 치솟음** — 과거 최악 사례(approach2 5차, 22.9%)보다도 심함. 원인: class_scale은 train만 보고 계산되는데, STES는 train과 test의 분포 차이(초과변이 비율 등)가 이미 확인된 클래스라 **train으로는 이 문제 자체가 안 보임**(CV로 검증 불가능한 함정).
- 옛날 고정 파일은 STES 배율을 0.5로 크게 낮춰뒀었는데(계산 출처 불명, 확인 필요), 이게 우연이든 의도든 이 문제를 완화하고 있었던 것으로 보임.
- **절충안 검토**: STES만 옛날 값(0.5)으로 고정하고 나머지 25개 클래스는 v7 전용 재계산 값 사용 → CV는 0.49662→0.49395로 소폭 하락(-0.0027)하지만, STES 과잉예측이라는 **실제 LB 하락과 상관관계가 확인된 위험**을 회피하는 보험 성격.
- **판단**: CV 손해(-0.0027, 추측)보다 STES 과잉예측 위험(과거 실제 LB 하락과 연관, 확인된 사실) 회피가 우선 — 이대로 제출은 보류, STES 고정 절충안을 검토 중.

### 부수 분석 — 13차(혜림님 신규 최고 LB) 상승분의 행 단위 분해
13차 제출(`approach19_hnsc_stes_soft_20260912_twin_rule.csv`, LB 0.44235, v7 대비 +0.00465)이 실제로 test의 몇 행을 어떻게 바꿨는지 두 파일(v7 원본 vs 혜림님 최종본)을 직접 비교해서 확인함.

**확인된 사실:**
1. test 2,546행 중 **딱 11행만** 예측이 바뀜(나머지 2,535행은 완전히 동일).
2. 그 11행의 변경은 **HNSC/STES/PCPG/GBMLGG/LGG/KIRC/KIPAN 7개 클래스 사이에서만** 일어남 — 두 종류의 서로 다른 메커니즘이 겹치지 않고 각자 작동:
   - **라우팅(3행, HNSC↔STES)**: 근거는 순수 모델 판단(로지스틱회귀 확신도 ≥0.70). train에 완전 동일 쌍둥이가 없어 정답 여부 확인 불가.
   - **twin_rule(8행, KIRC↔KIPAN 6행 + GBMLGG↔LGG/PCPG 2행)**: 전부 train에 변이 1~2개짜리 완전 동일 쌍둥이 행이 실제로 존재(`3. docs/04_duplicate_twins.md`의 99~100% 검증된 FLIP 규칙과 일치) — 정답일 가능성 높음.
3. Public LB가 test 100%를 그대로 채점하므로(샘플링 없음), **+0.00465는 수학적으로 전부 이 11행에서만 나온 것** — 다른 원인은 불가능.
4. 작은 클래스일수록 같은 개수의 예측 변경이 그 클래스 F1을 더 크게 움직임(DLBC(38개)/LAML(158개)/KIPAN(515개) 비교로 검증: 표본이 13배 작으면 변화폭도 13배 커짐) — macro F1은 클래스 크기로 가중하지 않고 평균하므로 이 효과가 그대로 전체 점수에 반영됨.
5. **다만 test의 실제 클래스별 표본 수(분모)를 모르기 때문에, +0.00465를 "몇 행이 정답이 됐다"는 식으로 정확히 수학적 분해하는 것은 현재 불가능함.** train 표본 크기로 추정한 값을 실제 LB 상승분과 직접 비교하는 시도(예: "train 구조로는 +0.0013만 나온다")는 train 비율 추정치를 test 실측값처럼 다루는 오류라 결론에서 제외함.

**결론: LB 상승의 출처(어느 행, 어느 클래스, 어느 메커니즘)는 명확히 설명되지만, 그 상승폭의 정확한 크기는 test 라벨이 없는 한 설명할 수 없음.** 8행(twin_rule)의 신뢰도는 높고 3행(라우팅)은 불명확하다는 점 외에, 이 이상의 정량적 분해는 대회 종료 전에는 불가능.

v21의 STES 고정 절충안을 다듬어(HNSC도 함께 고정 필요함을 발견) 실제 test 추론·LB 제출까지 진행한 내용과, 그 과정에서 처음으로 격리 측정된 twin_rule 단독 효과(+0.00478)는 별도 문서 `2. team/approaches/approach22.md`에 기록함(사용자 지시: 새 제출 파이프라인은 approach11의 버전이 아니라 별도 approach22로 관리).

### v22 — 다른 혼동 쌍으로 라우팅 확장 시도 (`approach11_twin_handling_v22_pair_search/`)
approach19(혜림님, HNSC/STES)와 같은 레시피(변이율 차이 상위 40유전자, 로지스틱회귀 C=0.1, 확신도 임계값 0.70)를 **다른 혼동 쌍에도 적용 가능한지** 확인. 매번 메인모델을 재학습하지 않도록, v11 캐시(`6. experiments/2026-09-12_approach11_v11_integration/oof_main_cache.pkl`, 시드 42/7/123/2024/999)의 fold 배정을 재현해서 재사용(`pair_router_check.py`, `solo_class_check.py`) — 재학습 없이 서브모델만 새로 학습해 수십 초 안에 검증.

**먼저 train 정직 CV 혼동행렬(5시드 평균, class_scale 적용 전 원본 모델 기준)로 상위 혼동 쌍을 추출**해 후보를 골랐음(BRCA가 낀 쌍은 "가장 큰 클래스가 끌어당기는 현상"으로 보고 pairwise 라우팅 후보에서 제외).

| 쌍 | 양방향 혼동(5시드 평균) | 방식 | 결과 |
|---|---|---|---|
| LUAD ↔ LUSC | 31.8건 | pairwise | 탈락 — mean_delta=-0.00022, std=0.00035, 1/5 양수 |
| UCEC ↔ CESC | 6건 | pairwise | 탈락 — mean_delta=-0.00023, std=0.00017, 1/5 양수 (애초에 혼동 자체가 약함) |
| HNSC ↔ LUSC | 33.4건 | pairwise | 탈락 — mean_delta=-0.00024, std=0.00030. 실제 개입(서브모델이 메인과 다른 답을 낸 행)은 8건뿐이고 그마저 도움 3/손해 3/무관 2로 신호 없음 |
| PCPG ↔ THCA | 30.0건 | pairwise | 탈락(확실) — 5시드 전부 개입 0~1건, 확신도 0.7을 넘는 경우 자체가 거의 없음(둘 다 변이 개수가 원래 적어 상위 40유전자 판별력이 약함) |
| PAAD ↔ LIHC | 1건 미만 | pairwise | 시도 전 기각 — 애초에 서로 거의 안 헷갈림(모델이 이미 잘 구분), 표본 크기는 적당해도 라우팅이 성립할 혼동 자체가 없음 |
| PAAD (단독) | - | one-vs-rest, 임계값 0.85 | 탈락 — mean_delta=-0.00270, 5/5 음수. 개입 시 정답전환:오답전환 ≈ 1:3.7 |
| LIHC (단독) | - | one-vs-rest, 임계값 0.85 | 탈락 — mean_delta=-0.00885, 5/5 음수. 정답전환:오답전환 ≈ 1:4.6 |
| LUSC ↔ STES | 49.2건 | pairwise | 검증 중 보류(STES 관련이라 STES 배율 문제와 얽혀서 별도 판단 필요) |

PAAD/LIHC는 개별 F1이 낮은데도(0.282/0.345) 오답이 특정 상대 클래스 하나가 아니라 여러 클래스로 흩어지는 패턴이라(예: PAAD는 OV·STES·BRCA·HNSC·GBMLGG로 분산), pairwise가 아니라 one-vs-rest 구조로 시도했으나 이것도 실패함 — 확신도 0.85로 높여도 오답 전환이 정답 전환보다 훨씬 많음.

**결론: HNSC/STES(approach19) 외에는 지금까지 시도한 어떤 혼동 쌍·단독 클래스도 신호가 없음.** 이 레시피 자체가 HNSC/STES에 특별히 잘 맞았던 것이지, 다른 쌍에 일반화되는 방법론은 아닌 것으로 보임. LUSC/STES와 COAD/STES(STES 얽힌 나머지 후보)만 STES 배율 이슈 정리 후 재검토 대상으로 남겨둠.
