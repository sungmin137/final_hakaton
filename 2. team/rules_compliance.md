| ✅ 도메인 지식 | 논문·교과서의 원리, BLOSUM62 치환 행렬, 아미노산 물리화학 특성(소수성·전하·부피), 유전자 기능 분류(oncogene/TSG) 상식 | 허용으로 해석. 피처 설계에 반영. DACON 게시판에도 BLOSUM62 활용 코드가 공개 공유됨 |

원칙: **환자·샘플 단위 데이터는 어떤 형태로도 들여오지 않는다.** 지식 기반 피처는 출처(논문·행렬 이름)를 문서에 남겨 발표에서 설명 가능하게 한다.
구현: `4. src/common/approach2_knowledge/knowledge_features.py` (BLOSUM62 + 아미노산 특성 변화량). 출처: Henikoff & Henikoff 1992 (BLOSUM62), Kyte & Doolittle 1982 (소수성), Zamyatnin 1972 (잔기 부피).

## 2026-09-14 재점검 — 9/13~9/14 추가분 (규칙 원문: "모델 학습에 평가 데이터셋 활용 시 수상 제외 — 인코딩·스케일링·get_dummies·결측 처리에 test 활용 포함")

### 결론
- **공식 규칙 위반은 없다.** test로 학습·인코딩·스케일링·결측 처리한 코드가 없다(`load_test`는 추론 함수 안에서만 호출).
- **팀의 엄격 기준으로는 두 가지가 회색이다.** (1) 초과변이 규칙의 발견 계기가 test 예측 점검이라는 점(매개변수는 train), (2) 22차의 test 행 간 동일성 사용. (2)는 폐기 확정, (1)은 발견 경위를 숨기지 않고 설명하는 조건으로 유지 권고.
- 앞으로의 원칙: test 예측은 **관찰까지**. 임계·가중치·허용 집합 같은 값은 반드시 train에서 나와야 하고, test 행 간 관계(동일성·근접성)는 쓰지 않는다.

## 2026-09-14 기준 확정 (사용자 결정): **test 데이터 분석 자체 금지. 모든 근거는 train에서.**
공식 규정(학습·전처리 fit 금지)보다 엄격한 기준을 팀 기준으로 확정한다. 이에 따른 재판정:

| 항목 | 새 기준 판정 | 조치 |
|---|---|---|
| 두 모델 블렌드·배율 복원·쌍둥이 규칙(행 단위 추론)·결측 상수 처리 | ✅ train 근거 | 유지 |
| **21차 초과변이 규칙** | ⚠️ 매개변수는 train(임계 396 = ACC 최대, 허용 집합 = train 초과변이 ≥2회 클래스)이고 도메인 근거(초과변이는 POLE/MSI형 UCEC·COAD·STES, UV형 SKCM에서 생기며 ACC·DLBC·SARC·LUSC는 초과변이 암종이 아님)로 test 없이도 세울 수 있는 규칙이다. **그러나 실제 발견 경위는 test 예측 점검(ACC 예측 18행의 변이 900+)이었다.** train만으로 정의한 일반형(클래스별 변이 수 범위 규칙, `postprocess/class_range_rule.py`)은 정직 OOF에서 0.4941 → 0.4915로 **손해**(fold별 범위가 극단 1~2행에 좌우됨). 초과변이형(임계 396·허용 집합)은 train 초과변이 행이 OOF에서 이미 잘 맞아 2행만 건드려 **train으로는 검증 불가** | 팀 판단 필요. 유지한다면 발표·문서에 "규칙 값은 train과 도메인 지식, 발견 계기는 test 예측 점검"을 그대로 밝힌다. 새 기준 아래서는 같은 방식의 발견을 **더 하지 않는다** |
| 22차 test 행 간 동일 쌍 규칙 | ❌ | 폐기 확정 |
| 상피 동결 하이브리드(`hybrid_epifreeze*`, `hybrid_on21`) | ❌ test 예측 변화 + LB 분해로 행을 고름 | **제출 후보에서 제외** |
| 제출 전 STES 비율·이동 클래스 점검 | ❌ test 예측 분석 | **중단**. 제출 전 점검은 형식(행 수·열·라벨 집합)만 |
| `3. docs/05_test_inference.md`, `3. docs/08_test_shift_diagnostics.md` | ❌ test 분석 문서 | 기록으로 보존하되 **어떤 결정의 근거로도 쓰지 않음**(문서 머리에 표시) |
| hypermut2(>600 CESC), 마커 일관성 규칙 | ❌ / ✅(OOF 실패) | 둘 다 폐기 |

앞으로의 유일한 채택 기준: **정직 CV(쌍둥이 묶음)에서 이득이 확인된 train 전용 변경**, 또는 train 통계 + 도메인 지식만으로 사전에 정의한 규칙. test 예측 분포·행 수·클래스 이동은 보지 않는다.
