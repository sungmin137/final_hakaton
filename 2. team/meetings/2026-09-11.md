# 회의 공유 자료 (2026-09-11) — approach11 라우팅 앙상블 결과와 다음 방향

## 오늘 오전~오후 LB 제출 기록 (성민님 mild 변형 + 회원님 approach11 라우팅)
| 차수 | 파일 | 바뀐 것 | 정직 CV | LB |
|---|---|---|---|---|
| 9차 | approach2_v7 | 3차 구성 + colsample_bytree 0.7 | 0.469 | **0.4377 (신규 최고)** |
| 10차 | approach2_v8 | 3차 구성 − cw_variant 제거 | 0.469 | 0.4297 |
| 11차 | approach2_v12 | v11(0.7+잎규제) + colsample 0.5(강한 규제) | 0.4712(CV 최고) | 0.4112(LB 최저) |
| 12차 | approach11_v5 | v7 설정(colsample 0.7+복원 배율) + GBMLGG/LGG 전용 서브모델 라우팅(approach11 v4 로직) | 0.4669 → 라우팅 0.4693(+0.0024) | **0.4331 (v7 대비 −0.0046, 역효과)** |

**패턴**: 9~11차는 colsample을 0.7→0.5로 낮출수록(정규화를 강하게 할수록) CV는 계속 좋아졌는데 LB는 계속 나빠짐. 12차(회원님 라우팅 앙상블)도 CV는 개선(+0.0024)인데 LB는 하락(−0.0046) — **네 번의 제출 모두 "CV상 개선처럼 보이는 변경이 LB에서는 반대로 나오거나 손해"라는 같은 패턴을 보임.**

## 왜 역효과였는지 (원인 진단)
GBMLGG/LGG 서브모델이 학습한 실제 데이터를 뜯어보면:

| 클래스 | 전체 행 | 쌍둥이(구분 불가) | 비쌍둥이(진짜 학습재료) |
|---|---|---|---|
| GBMLGG | 461 | 175 | 286 |
| LGG | 229 | 177 | **52** |

- LGG를 "진짜로" 구분해서 배울 수 있는 행이 **52개뿐**. 4,384개 유전자 컬럼짜리 데이터에서 52개 표본으로는 사실상 노이즈를 외운 것에 가까움.
- 게다가 서브모델 학습에 쌍둥이 행(352개, 프로필은 같은데 라벨만 GBMLGG/LGG로 반반 갈림)까지 섞여 들어가서, 모델이 "똑같이 생긴 입력에 다른 정답"을 동시에 학습함 — 그 자체로 노이즈.
- train 정직 CV(5-fold)는 이 52개를 5등분해서 매 fold 10개 안팎으로 채점 → 표본이 작아 결과가 운에 크게 좌우됨. **v4의 +0.0012~0.0024 개선은 이 작은 표본에서 우연히 맞은 결과였을 가능성이 큼.**

**참고**: 같은 방식이 KIRC/KIPAN에도 적용 가능해 보였지만, KIRC도 비쌍둥이 학습재료가 58개뿐이라 (approach11 v2/v3에서 KIRC 전용모델 비쌍둥이 정확도 17~21%로 이미 낮게 나왔음) 똑같은 문제를 안고 있었음 — 그래서 애초에 KIRC/KIPAN은 라우팅 대상에서 제외했던 판단이 맞았음.

## 다른 혼동 클래스 쌍 (메인모델 혼동행렬 분석)
| 클래스 A | 클래스 B | 오답 합계 |
|---|---|---|
| KIPAN | KIRC | 230 |
| GBMLGG | LGG | 203 |
| BRCA | OV | 141 |
| BRCA | PRAD | 134 |
| BRCA | KIPAN | 107 |
| BRCA | SARC | 80 |
| PRAD | THCA | 63 |
| HNSC | STES | 62 |

- **BRCA가 낀 쌍들**: BRCA는 train에서 가장 큰 클래스(786행, 12.7%)이고 쌍둥이는 5행뿐이라, 쌍둥이 문제가 아니라 **클래스 불균형** 때문에 애매한 행을 BRCA로 찍는 경향으로 추정됨. GBMLGG/LGG와는 원인이 다름 — 같은 "서브모델+라우팅" 처방을 그대로 쓰면 안 되고 별도 진단 필요.
- **PRAD↔THCA, HNSC↔STES**: 표본이 충분히 큼(200~380행) — LGG처럼 표본 부족 문제는 아니라서, 오히려 두 클래스를 구분하는 피처가 있는지부터 확인해볼 만함.

## 다음 방향 제안

### 1. GBMLGG/LGG 라우팅 개선판
이번 실패 원인(쌍둥이 행 섞임 + 표본 52개로 과적합)을 하나씩 보정한 버전:

- **(a) 서브모델 학습에서 쌍둥이 행 제외**: 지금까지(v2~v5) 서브모델은 GBMLGG/LGG 전체 690행(쌍둥이 352행 포함)으로 학습했음. 쌍둥이는 프로필이 완전히 똑같은데 라벨만 GBMLGG/LGG로 반반 갈리는 행이라, 이걸 학습에 넣으면 모델이 "똑같이 생긴 입력에 서로 다른 정답"을 동시에 배우는 셈(순수 노이즈). 비쌍둥이만(GBMLGG 286 + LGG 52 = 338행)으로 학습시켜서 모순된 신호부터 제거.
- **(b) 표본 52개에 맞는 단순 모델**: 52개 표본에 4,384컬럼짜리 XGBoost는 차원 대비 표본이 터무니없이 적어 과적합 위험이 큼. 로지스틱회귀+강한 L2 정규화, 또는 IDH1처럼 이미 알려진 소수 유전자 마커만 쓰는 단순 모델로 교체.
- **(c) 신뢰도 임계값 라우팅**: 서브모델이 확신할 때만(예: 확률 0.7 이상) 메인 모델 예측을 덮어쓰고, 애매하면 메인 모델 그대로 유지. 지금은 서브모델이 확신 없어도 무조건 덮어쓰는 구조라 이 부분이 위험 요인이었음.
- **(d) 쌍둥이 test 행은 라우팅 대상에서 제외**: test 행이 train의 쌍둥이 그룹과 프로필이 완전히 같은지는 이미 있는 `TwinRule`로 확인 가능함. 즉 test 행을 두 종류로 나눌 수 있음 — ① train 쌍둥이 그룹과 프로필이 완전히 같은 행 → 서브모델 안 쓰고 메인 모델(또는 쌍둥이 규칙) 답 그대로 유지, ② 그런 매칭이 없는 행(비쌍둥이 성격) → 서브모델로 덮어쓰기 시도. "쌍둥이는 포기"가 아니라 **"쌍둥이는 원래 하던 대로 메인 모델이 맡고, 비쌍둥이만 서브모델이 새로 도전"**하는 구조가 됨 — 메인 모델이 지금까지 쌍둥이 행에 대해 내던 정확도는 그대로 유지됨.
- **(e) 제출 전 반복 CV로 사전 필터링**: 시드 5~10개로 반복 CV를 돌려서 개선폭 대비 표준편차가 크면(=결과가 운에 좌우되는 수준이면) 애초에 제출 후보에서 제외. 여러 신뢰도 임계값(0.6/0.7/0.8)에서 실제로 몇 개 행이 라우팅될지도 test 확률 데이터로 미리 계산해서, 라우팅되는 행이 너무 적으면(=v7과 사실상 동일한 결과) 제출하지 않음.

**참고**: 이 틀(전용 서브모델 + 신뢰도 임계값 + 반복 CV 분산 검증) 자체는 GBMLGG/LGG·KIRC/KIPAN에만 국한되지 않고, 아래 BRCA·PRAD↔THCA·HNSC↔STES 같은 다른 혼동 쌍에도 적용해볼 수 있는 일반적인 틀임. 다만 "쌍둥이 제외"(a)와 "쌍둥이 test 행 감지"(d)는 프로필이 완전히 동일한 쌍둥이 구조가 있는 GBMLGG/LGG·KIRC/KIPAN에만 의미가 있고, 다른 쌍은 애초에 이런 쌍둥이 현상이 없어서 해당 없음.

### 2. BRCA 관련 혼동
클래스 불균형 문제로 보이므로, 서브모델보다는 클래스 배율(class_scale, 이미 검증된 방식) 조정이나 손실 가중치 재조정이 더 맞을 수 있음.

### 3. PRAD↔THCA, HNSC↔STES
표본은 충분하니, 서브모델보다는 이 쌍을 구분하는 데 도움될 피처가 있는지 먼저 탐색.

## 결론
1. **무조건 서브모델 값으로 덮어쓰는 하드 라우팅은 폐기하고, 신뢰도 임계값 기반 소프트 라우팅으로 방향을 바꿈.** 서브모델이 확신할 때만(예: 확률 0.7↑) 메인 예측을 덮어쓰고, 애매하면 메인 모델을 그대로 둠.
2. CV 개선이 LB로 안 이어지는 패턴이 (1) 배깅, (2) 규제 강화, (3) 클래스 라우팅 — 세 가지 서로 다른 축에서 반복 확인됨. **그러니 앞으로는 "CV만 보고 모델을 통째로 덮어쓰거나 규제를 세게 미는" 시도를 피함.** 변경 하나당 자유도를 최소화하고, 변경 전후를 1:1로 비교할 수 있는 형태로만 시도함.
3. **CV는 버그·붕괴 감지용으로만 씀.** 개선폭이 +0.001~0.003처럼 작을 때는, 그 결과를 바로 제출하지 않고 다음 절차를 반드시 거침:
   - ① 저장된 test 확률로 임계값별(0.6/0.7/0.8) 라우팅 대상 행 수를 미리 계산 — 너무 적으면(v7과 사실상 동일) 제출 보류
   - ② 시드 5~10개로 반복 CV를 돌려 표준편차 확인 — 개선폭보다 편차가 크면 제출 보류
   - ③ 둘 다 통과할 때만 리더보드에 제출
