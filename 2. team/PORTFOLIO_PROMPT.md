당신은 데이터 사이언스 포트폴리오 편집자입니다. 아래 프로젝트 기록을 바탕으로 포트폴리오 항목을 작성해 주세요. 사실은 기록에 있는 것만 쓰고, 수치·날짜·명칭을 바꾸거나 부풀리지 마세요. 기록에 없는 내용이 필요하면 `[확인 필요]`로 표시하세요.

## 출력 형식
1. **한 줄 소개** (40자 내외, 이력서용)
2. **3줄 요약** (문제 · 핵심 기여 · 결과)
3. **상세 섹션** (포트폴리오 본문, 600~900자): 배경과 문제 → 데이터에서 발견한 구조 → 접근과 반복 과정 → 최종 모델 → 결과 → 배운 점. 소제목 사용, 표 1개 이내.
4. **기술 키워드** 10개 이내
5. **면접 예상 질문 5개와 답변 요지** (각 2~3문장). 특히 "CV와 LB가 왜 달랐나", "데이터 누수를 어떻게 막았나", "실패에서 무엇을 배웠나"를 포함.
6. 톤: 1인칭, 담백하게, 형용사 최소화. 팀 프로젝트이므로 내 기여와 팀원 기여를 구분.

## 프로젝트 기록

**개요**
- 이름: [K-디지털 트레이닝 AI 헬스케어 6기] 최종 해커톤 — 유전자 변이 기반 암 아형 분류
- 기간: 2026-09-09 ~ 09-18 (10일). 팀 3인(성민 = 나, 혜림, 혜성). 내 역할: 주 파이프라인 설계·구현, 검증 체계, 팀 문서·저장소 운영.
- 과제: 환자 한 명의 유전자 변이 프로파일(유전자 4,384개 열, 값은 WT 또는 아미노산 변이 문자열)로 암 아형 26종을 다중 분류. train 6,201명, test 2,546명. 평가 Macro F1, Public LB = test 100%.
- 규칙: 외부 데이터 금지, 하루 4회 제출, test를 학습·전처리 fit에 쓰면 수상 제외. 팀은 더 엄격하게 "test 데이터 분석 자체 금지, 모든 근거는 train"으로 정함.
- 결과: **Public LB 0.49598 (팀 최고, 34회 제출 중 32차)**, 시작 0.415 대비 +0.081. 최종 제출은 test 근거를 전혀 쓰지 않은 구성. 저장소: github.com/sungmin137/final_hakaton (private).

**데이터에서 발견한 것 (전부 train)**
- 같은 환자가 두 라벨로 두 번 들어 있는 "쌍둥이" 중복(KIPAN↔KIRC 276쌍, GBMLGG↔LGG 173쌍, 완전 동일 행). 일반 K-fold CV가 +0.05 부풀려짐 → 쌍둥이를 같은 fold에 두는 그룹 K-fold("정직 CV") 도입. 1차 제출이 CV 0.494 / LB 0.41로 어긋난 원인.
- 클래스별 변이 수 중앙값이 2(THYM)~85(SKCM)로 극단적. 저변이 클래스(SARC·PRAD·PCPG·THYM·OV)는 원리적으로 정보가 부족.
- 클래스별 표지 유전자(COAD APC 72%, LGG IDH1 79%, KIRC VHL 45%, LAML NPM1 26%), ACC의 동의변이 배치 표지.
- 변이 표기(HGVS)를 파싱해 missense/동의/종결/프레임시프트/기타로 분류, 위치 추출.

**접근의 흐름과 시행착오**
1. 클래스별 변이 개수 가중치 점수(NB 로그우도비, 내부 OOF) 140개 → XGBoost: LB 0.415.
2. 클래스 배율 후처리(train OOF 좌표 상승, 26개) + 쌍둥이 규칙(train과 동일한 test 행은 짝 라벨): 0.437.
3. 실패 계열: 문헌 driver 피처, 전처리 확장 합치기, CatBoost·배깅 앙상블, 강한 규제, 라우팅·재판기 — CV는 올라도 LB 하락. 결론: "새 정보를 원본 열로 주면 트리가 무시한다", "같은 정보의 재표현은 블렌드해도 안 옮겨진다", "판단은 LB로, 한 번에 한 요소".
4. 첫 도약(16차 0.456): 변이 유형 분리(missense/절단/동의) 점수 모델을 따로 만들어 기존 모델과 로그평균. 다른 정보를 가진 모델의 결합만 LB로 옮겨짐.
5. 규정 회색 사례: test 예측을 점검하다 만든 초과변이 규칙이 LB 0.469를 냈으나, 팀 기준(test 분석 금지)에 따라 최종에서 제외하고 경위를 문서화.
6. 둘째 도약(23차 0.475): 아미노산 치환 스펙트럼(20×20 치환 쌍 비율, 행 내부 정규화라 fit 통계 없음). 변이 서명(UV·흡연·POLE·MSI·APOBEC)이 치환 분포로 드러난다는 도메인 근거.
7. 팀원 기여(혜림, 26차 0.480): 치환 프로필 MultinomialNB를 파트너 모델로. (혜성: 신장·뇌 서브모델 라우팅 v1~v22 검증, 배율 재계산 검증 — 둘 다 폐기 결론을 확정.)
8. 셋째 도약(32차 0.496): NB 점수표(클래스별 로그확률 26열, 내부 OOF)를 파트너가 아니라 주 모델의 피처로(v4sn, 단일 모델 최고 0.5324). 첫 시도는 피처 등록 버그로 골격이 빠져 실패(27차 0.464) → 버그 발견·수정·재실행으로 정정. 비중 조정(v4sn .45, NB 파트너 .1)으로 정점.
9. 마감일: 파트너 추가·변형·원본 열 제거·배율 재적합 등 CV로 전부 닫힘. v21이 CV·LB 모두 날카로운 최적점.

**최종 모델(v21)**: XGBoost 4개(v4s .10 / v4sn .45 / v2 .20 / v4sp .15) + MultinomialNB 파트너 .10을 로그 가중 결합 → train OOF로 고정한 클래스 배율 26개 곱 → argmax → 쌍둥이 규칙. 정직 CV 0.5433 → LB 0.4960(차이는 test에 고변이 행이 2.4~4.7배 많은 분포 차이).

**공정·재현성**: 제출 csv와 재현 스크립트 1:1, 두 번 실행 md5 동일 확인, 저장 확률 재사용으로 재학습 편차 배제, CV 실행기(인자 검증·로그·골격 자가 점검), 접근별 문서·제출 색인·실험 로그·규칙 대조표 운영. Jupyter 노트북으로 최종 파이프라인 재현.

**배운 점**: CV는 LB 절대값을 예측하지 못하며(−0.03~−0.07) 옮겨지는 변경은 "새 정보 모델의 로그평균"뿐이었다. 새 정보는 클래스별 집약 점수나 행 내부 비율 형태로 넣어야 트리가 쓴다. 배율은 고정, 큰 규칙·스태킹·재표현은 금물. 실수(셸 변수 분리, 피처 등록 누락)를 자동 점검으로 막는 공정이 결과만큼 중요했다.

**기술**: Python, pandas, NumPy, scikit-learn(StratifiedGroupKFold, MultinomialNB, LogisticRegression), XGBoost, 정규식 파싱, 로그 결합 앙상블, Macro F1 최적화, Git/GitHub PR 협업, Jupyter.
