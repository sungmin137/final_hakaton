## CV ↔ LB 대응 (2026-09-10 분석)
제출 5개의 (정직 CV, LB)로 검증 방식 5종(전체 / 31~100구간 / 31이상 / 비쌍둥이 / test 구간 재가중)의 순위 상관을 계산 → **모두 |Spearman| ≤ 0.3, 사실상 0**.
즉 CV 0.45~0.52 범위의 차이는 LB(0.412~0.437)를 전혀 예측하지 못한다. LB 격차(평균 −0.08, 편차 ±0.03)는 test 분포 차이에서 오고 train 안의 어떤 재가중으로도 재현되지 않는다.
→ 제출 선택은 LB로만 한다. CV는 버그 감지(예: 0.27 붕괴)와 큰 회귀 방지용으로만 쓴다.

## 13차 (2026-09-12, 팀 신규 최고 기록)

### 13차 결론
- **팀 최초로 CV↔LB가 같은 방향(둘 다 최고)으로 나온 사례.** 다만 CV 개선폭(+0.00045)이 LB 개선폭(+0.00465)의 1/10 수준이라, **차액(+0.0042)의 상당 부분이 라우팅이 아니라 함께 적용된 쌍둥이 규칙(twin_rule) 때문일 가능성이 있음** — twin_rule 단독 효과는 정직 CV로 측정이 원천적으로 불가능하다는 게 이번 세션에서 별도로 확인됨(라우팅과 twin_rule을 한 번에 켠 제출이라 원인 분리 안 됨, `2. team/approaches/approach11.md` 참고).
- **class_scale 관련 후속 발견(제출 전, CV만 확인됨, 아직 미제출)**: 13차를 포함한 v7 계열의 모든 제출이 2026-09-09에 다른(v7 이전) 모델로 한 번 계산된 고정 class_scale 파일을 그대로 재사용해왔음이 확인됨. v7 자신의 정직 CV로 배율을 다시 계산하면 CV가 크게(+0.014~0.019) 오르지만, **STES 배율을 건드리지 않게 돼서 실제 test 추론 시 STES 예측 비율이 23.3%까지 치솟는 위험 신호 발견**(train 내에서는 6.8%로 정상). STES 과잉예측은 과거(5차, approach2 5차 등) LB 하락과 상관관계가 확인된 패턴이라 **이대로 제출하지 않음**. STES 배율만 옛날 값(0.5)으로 고정하는 절충안을 검토함 — 실제 시도는 아래 14~15차, 상세는 `2. team/approaches/approach22.md` 참고.
